Dataset Documentation

This documentation explains what datasets are, how they are organized, how to choose the right one, and how to request and manage datasets through the Tag Management Dashboard.

Introduction

The Tag Management Dashboard is a self-service tool that allows researchers, program leads, evaluators, and administrators to generate curated datasets for reporting, analysis, and program evaluation.

Rather than requiring users to write complex SQL queries or understand the structure of the underlying data warehouse, the Tag Management Dashboard provides pre-built dataset templates that can be filtered and customized to meet specific reporting needs.

Datasets are generated as Snowflake tables and can be refreshed with one click, allowing a user to create a table once and refresh it as needed for annual reporting or other reporting requirements.

This documentation describes:

  • What datasets are
  • How datasets are organized
  • How to select the appropriate dataset
  • How tags influence dataset creation
  • How to request and manage datasets
  • How datasets can be combined to answer more complex research questions

What Is a Dataset?

A dataset is a curated query template designed to answer a specific set of business, programmatic, or research questions. Each dataset represents a particular domain within the learning ecosystem and returns data that has already been organized and standardized for analysis.

Examples include:

  • Enrollment and completion information
  • Learner assessment results
  • Course access patterns
  • Assignment submissions
  • Survey responses
  • Instructor engagement

When a user submits a dataset request, the system generates a Snowflake table based on the selected dataset and the filters provided. The resulting table can then be used for:

  • Reporting
  • Research
  • Program evaluation
  • Dashboard development
  • Ad hoc analysis

Why Datasets Are Curated

Datasets are intentionally divided into separate subject areas for several reasons:

Accessibility: Users can request datasets without needing to know table relationships, field names, or coding languages, which makes the data accessible to a much wider audience.

Simplicity: Most users do not need access to every available source table. Curated datasets provide information organized around common reporting needs.

Consistency: Researchers and program teams can work from the same fields when producing reports.

Performance: Users can retrieve only the information relevant to their analysis instead of querying large volumes of raw data.

Flexibility: Different datasets answer different questions and support different audiences.

Source System Separation: Datasets are organized according to the enterprise systems from which the information originates.

Understanding Tags

Our dataset collection relies heavily on the tagging framework created by the Data Management Team. Tags help organize courses, sections, assessments, and survey questions into meaningful classifications.

Many dataset filters are driven directly by tags, although users of the Tag Management Dashboard's section tags will only handle section tags. Users should have a basic understanding of the tagging framework prior to requesting data.

Section Tags

Section tags classify courses and sections.

Common section tag categories include:

Program: Identifies the program to which a course or section belongs. Examples include :

  • Literacy Coach Endorsement
  • Math Micro-Credential
  • Early Learning

Segment: Identifies academic-year cohorts and reporting periods — from July 1 of a year to the following year's June 30. The Data Management team automatically generates Segment tags based on a course section's start date.

OKR: Aligns courses and sections to organizational groupings or departments. Examples include

  • New Worlds Reading,
  • Literacy
  • Early Learning.

Assessment Tags

Assessment Tags are used to track learner growth and course efficacy.

  • Pre-Assessment
  • Post-Assessment

Question Tags

Question tags support reporting across surveys. Examples include:

  • Demographic information
  • Professional role in education
  • Years of experience
  • Net Promoter Score questions
  • Other evaluation-related measures

Common Research Questions

The Dataset Guide provides examples of questions each dataset can answer. Common examples per dataset include:

Enrollments:

  • How many learners enrolled?
  • How many completed? How many dropped?
  • How long did completion take?

Assessments:

  • Which questions were most frequently missed?

  • Would they recommend the experience?
  • What themes appeared in qualitative responses?

Creating Your Own Dataset

Users who have access to creating a dataset will follow seven simple steps.

Step 1: Select a Dataset

Choose the dataset that most closely aligns with your reporting question. If you are unsure which dataset to select, review the Dataset Guide before proceeding.

Step 2: Apply Filters

After selecting a dataset, available filters will appear. Use filters to narrow the data included in your request. The toggle in the Tag Sections part allows a user to add an additional tag filter, which would result in a dataset that meets both tag filter criteria. This is helpful when creating a dataset that is a subset of two larger overlapping tags. For example, if a funding source crosses over programs and a user wants to see all the sections tagged as that funding source within only one program, they would filter with both Research/Funding and Program tags.

Selecting anonymization on your dataset will return hidden information for users' names, emails, and any other information that can identify them. It is not required for Lastinger associates to use anonymized datasets; this is available for datasets requested by researchers outside of the Lastinger Center.

Step 3: Create a Table Name

Provide a short, descriptive Snowflake table name. Examples include:

  • Bunn_Enrollments_Early_Childhood_State_Appropriations_Report_25_26
  • Mendez_Surveys_Jim_Moran_Annual_25_26

Step 4: Add a Description

Provide a brief description explaining the purpose of the dataset. Examples include:

  • This table captures the enrollments dataset filtered by OKR tag Early Childhood, Funding tag Early Childhood Systems, and Segment 2025-26. This dataset was created for the 2025-26 State Appropriations Report.
  • This table captures survey responses for all sections with the Research/Funding tag of The Jim Moran Foundation. This dataset was created to pull quotes for the 2025-26 annual report.

Step 5: Review Saved Location (Schema)

From a UFL username, the system automatically determines where the resulting table will be saved within Snowflake. This value will be in the web URL for your table:

https://app.snowflake.com/ufl/datahub/#/data/databases/PUB_LAKE_LASTINGER/schemas/[your_schema_name]

For members of the Data Management Team that create tables to be used in center-wide reporting, overwrite the default username value and change the schema name to “final”. These tables will then be accessible to any associates with Snowflake access.

Step 6: Submit the Request

Once submitted, the request will be processed, and the resulting table will be generated by the morning of the following business day. Requests are automatically approved for authorized users.

Reviewing User Requests

After a request is submitted, it appears in the User Requests page. The User Requests page serves as a history of datasets created by the user and provides visibility into request status and refresh settings. The list will show your request's :

  • Dataset
  • Table Name
  • Schema
  • Description
  • Request Status
  • Creation Date
  • Last Updated Date
  • Toggle to Manually Refresh

Refreshing User Requests

To update the table, the user must manually refresh their dataset within the User Requests page by clicking the Refresh button. The updated dataset will replace the existing dataset by the morning of the following business day.

Combining Datasets for Advanced Analysis

Many reporting needs can be met using a single dataset. More advanced research questions may require multiple datasets. Datasets are designed to be combined when answering complex research questions.

Suggested Dataset Combinations

Research Goal Suggested Dataset(s)
Course efficacyEnrollments + Grades
Engagement and completionEnrollments + Course Access
Content usage and completionEnrollments + Content Progress
Learner feedback by programEnrollments + Surveys
Instructor impact analysisEnrollments + Instructors

These combinations are intended as guidance and may evolve as additional datasets become available. To analyze datasets across SIS and LMS, utilize the Sections dataset, which will provide SIS and LMS section identifiers.

Best Practices

Choose the simplest dataset first: Start with the dataset most directly aligned with your research question.

Use descriptive table names: Use names that clearly indicate the dataset, program, and reporting period.

Review the Dataset Guide: Always verify that the selected dataset contains the information needed before creating a request.

Use filters strategically: Applying appropriate filters reduces unnecessary data and improves usability.

Document your purpose: Descriptions make it easier to identify and reuse datasets later.
